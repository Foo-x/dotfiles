description: >
  既存コードの実装を読み、内容に適した図表を選んで、インタラクティブな単一HTMLとして図解する。
argument-hint: "<path...> [図表名 ...]"
disable-model-invocation: true
---

対象コードの実装を読み、図解したインタラクティブなHTMLを1つ出力してください。

引数: $ARGUMENTS

参照ファイル（必要になった時点で読む）:

- 図表の選定基準・抽出する情報・レイアウト指針: `${CLAUDE_SKILL_DIR}/references/diagrams.md`
- インタラクションの種類・実装規約: `${CLAUDE_SKILL_DIR}/references/interactions.md`

## 大原則

- 対象コードは変更しない
- コメント・ドキュメント・テスト・README は参照しない。実行されるコードだけを根拠にする（コメントと実装が食い違っていても、実装を真とするため）
- コードにない振る舞いを図に足さない。動的ディスパッチ・リフレクション・設定値や環境変数への依存など、静的に確定しない箇所は「推定」と明示する
- 図中の要素は必ずコード要素に紐づけ、ホバー／クリックで `file:line` とコード抜粋を確認できるようにする
- 外部依存のない単一HTML（インライン SVG + 素の JS/CSS）にする。CDN・外部フォント・外部画像は使わない

## 1. 読解

引数のパス（ファイル・ディレクトリ・関数名）を対象とする。指定がなければ AskUserQuestion で確認する。

対象コードを読み、以下を抽出する。

- モジュール・パッケージ、型・データ構造、関数・API、状態変数、エントリポイント、外部I/O（DB・HTTP・ファイル・キュー・環境変数）、並行実行単位、分岐条件、定数・設定値、時間制約（タイムアウト・リトライ・周期実行）

コード要素の識別:

- `C1, C2, ...` を採番し、`file:line` とコード抜粋を対応付ける
- 対象の境界（ライブラリ内部・生成コードなど対象外とするもの）と抽象化の粒度（モジュール単位・関数単位など）を決める

## 2. 図表選定

`references/diagrams.md` の対応表で、コードの特徴に合う図表を選ぶ。

- コンテキスト図は概観として原則含める
- 引数に図表名があればそれに従う
- 1つのコード要素が複数の図に現れてよい。図に無理に当てはめず、適するコード要素がなければその図は作らない

選定した図表・選定理由・対象の C・対象の境界と抽象化の粒度を AskUserQuestion で1回確認する。ユーザーは図表を追加・除外できる。

## 3. インタラクション設計

各図について `references/interactions.md` から手法を選ぶ。インタラクションが理解を助けない図は静的のままにする。

## 4. HTML 生成

カレントディレクトリに `<対象パスの basename>-visualize.html` を出力する。対象パスが複数なら `code-visualize.html` とする。

構成:

- ヘッダー: 対象パス・凡例（色・線種・記号の意味）
- 概観: コンテキスト図（あればモジュール構成図）と、コード要素と図表の対応マップ（どの図で何がわかるか）
- 図ごとのセクション: タブまたは目次で移動する。各図に「対象のコード要素」「読み方」を付ける
- 未反映: 図に載らなかったコード要素と、推定で補った箇所の一覧
- 共通
    - ダーク/ライト両対応の CSS 変数、レスポンシブ
    - ID は内容がわかるようにする（併記、またはホバーで名前と `file:line` を表示）。クリックでドロワーにコード抜粋（行番号付き）を表示する
    - コード要素のデータは `<script type="application/json">` に1か所で持ち、描画と分離する

## 5. 自己検証

- 全コード要素が図または「未反映」の一覧に現れること
- `references/diagrams.md` の「重なりの検査」に従い、要素が重ならずテキストが読めること
- 抽出した `<script>` に `node --check` が使えれば構文チェックする
- 条件切替・遷移再生などの結果がコードの分岐・代入と一致すること。評価ロジックには根拠の C と `file:line` を併記する
- ブラウザ自動操作（Playwright 等）が使えれば、コンソールエラーがないこと、各インタラクションが動くことを確認する

出力後は、ファイルパス・選んだ図表・図に載せられなかったコード要素（あれば）・推定で補った箇所（あれば）を簡潔に報告する。
