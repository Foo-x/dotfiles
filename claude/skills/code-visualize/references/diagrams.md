# 図表の選定基準

## 対応表

| 図表 | 主な対象コード | 補足 |
|---|---|---|
| コンテキスト図 | エントリポイント・外部I/O・外部サービス | 概観の起点。原則含める |
| モジュール構成図 | パッケージ・モジュール・型・関数の入れ子構造 | 概観としてコンテキスト図と並べる。対象が1ファイルなら不要 |
| 状態遷移図 | 状態フィールド・状態を更新する処理・ガード | 階層状態・並行状態も含める |
| ペトリネット | 並行実行・ロック・同期・資源の取り合い | |
| オブジェクト図 | 型定義・フィールド・参照・コレクション | クラス図/ER図（構造）を含め、具体例（インスタンス）とトグルで切り替える |
| シーケンス図 | モジュール・サービス間の呼び出し順序 | |
| コミュニケーション図 | モジュール・サービス間の接続関係 | シーケンス図と同じデータを別ビューで切り替える |
| 依存関係グラフ | import・モジュール依存・初期化順序 | |
| コールグラフ | 関数・メソッドの呼び出し関係 | |
| フローチャート | 関数内の分岐・ループ・例外 | 処理が複数のモジュールにまたがるならスイムレーンを使う |
| データフロー図 | 値の入力・変換・保存・出力 | |
| 決定表 | 複数条件の組み合わせ→分岐先 | 処理されない組み合わせ・到達不能・競合を見つける |
| トレース表 | 実行ステップ × 変数の値 | 実行トレースの意味に限る |
| 変数と制約の二部グラフ | 入力検証・事前条件・不変条件 | |
| ガントチャート | タイムアウト・リトライ間隔・周期実行 | タイミングチャートを含める |

## 図表ごとの指針

各図表は「シグナル → 抽出 → インタラクション → レイアウト」の順に記す。インタラクション名は `interactions.md` の番号に対応する。

### コンテキスト図

- シグナル: main・ルーティング・ハンドラ・CLI 定義・ジョブ登録、DB/HTTP クライアント・ファイル・キュー・環境変数へのアクセス
- 抽出: 中心に対象コード、周囲に呼び出し元（利用者・他システム）と外部I/O、辺にやりとりするデータ・操作。対象の境界の外は破線で区別する
- インタラクション: 1（外部要素のクリックで関連するコード要素をドロワー表示）、6（外部要素の選択で関連するコード要素・他の図を強調）
- レイアウト: 中央に対象コード、外部要素を円周上に配置。人・外部システム・データストアで形を変える

### モジュール構成図

- シグナル: ディレクトリ構成、パッケージ・名前空間・モジュール宣言、公開/非公開の区別
- 抽出: ディレクトリ/パッケージ → モジュール → 型・関数の入れ子と、モジュール間の依存の本数。公開範囲を記号で示す
- インタラクション: 1（入れ子の折りたたみ）、6（選択モジュールの依存先/依存元を強調）、5（階層移動）
- レイアウト: 入れ子の矩形（コンテナ）。依存の多いモジュールを隣接させ、依存は本数を太さで示す

### 状態遷移図

- シグナル: 状態を表す enum・定数・フラグのフィールド、それを更新する代入・メソッド、更新前の if 条件
- 抽出: ノード=状態、辺=操作[ガード]/副作用。初期状態（コンストラクタ・初期値）・終了状態、ガードで拒否される遷移も記す
- インタラクション: 3（操作ボタンで発火し前後状態と副作用を表示）、2（ガード条件のトグル）、1（階層状態の折りたたみ）
- レイアウト: 正常系の流れを左→右の主軸にし、異常系・戻りを下側に迂回させる。自己ループは上に付ける

### ペトリネット

- シグナル: ロック・ミューテックス・セマフォ・チャネル・スレッドプール・上限付きキュー・`await`/`join` による合流
- 抽出: プレース=状態/資源、トランジション=処理、トークン=件数/資源数。初期マーキングはプールサイズ・容量・初期値から決める
- インタラクション: 3（トークンゲーム。発火可能な遷移のみ有効化、デッドロックの可視化）
- レイアウト: 左→右の層状配置。プレースは円、トランジションは棒/四角

### オブジェクト図

- シグナル: クラス・struct・型定義、フィールド・参照・コレクション、ORM モデル・マイグレーション・スキーマ定義（ER 図として扱う）
- 抽出: 構造（型と関係・多重度）と、コード中のリテラル・初期値・定数から得られる具体例（インスタンスと属性値）
- インタラクション: 4（構造⇔インスタンスの切り替え）、1（属性の折りたたみ）、6（関係先の強調）
- レイアウト: 関連の多い型を中央に配置。多重度を辺の両端に付ける

### シーケンス図

- シグナル: モジュール・サービス間の呼び出し、HTTP/RPC、メッセージ送受信、コールバック、`await`、エラー時の代替処理
- 抽出: ライフライン=モジュール/サービス/外部、メッセージ=順序付きの呼び出しとデータ。正常系と異常系（例外・エラー応答）を分ける
- インタラクション: 3（ステップ送り・自動再生）、4（正常/異常のタブ、コミュニケーション図との切り替え）
- レイアウト: 上→下が時間。ライフラインは左→右に、やりとりの多い順に隣接させる

### コミュニケーション図

- シグナル: シーケンス図と同じ。順序より「どのモジュール同士が接続するか」が重要な場合
- 抽出: モジュール間のリンクと、辺上の番号付きメッセージ（シーケンス図のデータを再利用する）
- インタラクション: 4（シーケンス図との切り替え）、6（メッセージ番号の選択で前後を強調）
- レイアウト: モジュールを円周上に配置し、辺に番号とメッセージ名を付ける

### 依存関係グラフ

- シグナル: import・require、DI の登録、初期化順序、継承・実装
- 抽出: ノード=モジュール/コード要素、有向辺=依存。循環依存は強調する
- インタラクション: 6（上流/下流/影響範囲の強調、2点間の経路）、7（種別・モジュールで絞り込み）、9（大規模時）
- レイアウト: 依存先を左、依存元を右の層状配置。辺の交差を減らす

### コールグラフ

- シグナル: 関数・メソッドの呼び出し、高階関数・コールバック、イベントハンドラの登録、再帰
- 抽出: ノード=関数/メソッド、辺=呼び出し。同期/非同期・コールバックを線種で区別する。動的ディスパッチの呼び出し先は候補を列挙し「推定」とする
- インタラクション: 6（呼び出し経路の強調、2点間の経路）、1（モジュール単位の折りたたみ）
- レイアウト: 呼び出し元を左、呼び出し先を右の層状配置

### フローチャート

- シグナル: if・switch・ループ・早期 return・例外の送出と捕捉
- 抽出: 開始/終了、処理、判断（菱形）、分岐ラベル（条件式）。処理が複数のモジュールにまたがるならスイムレーン
- インタラクション: 2（判断の入力で通る経路を強調）、3（ステップ再生）
- レイアウト: 上→下。判断は「はい」を下、「いいえ」を横に出す

### データフロー図

- シグナル: リクエスト・引数・ファイル読み込みなどの入力、変換・集計、DB 書き込み・レスポンス・ファイル出力
- 抽出: プロセス（関数）、データストア、外部実体、データフロー（変数名・型名付き）
- インタラクション: 6（データ項目の追跡: 入力から出力までの経路を強調）、1（プロセスの分解）
- レイアウト: 外部実体を両端、プロセスを中央、データストアを下側に置く

### 決定表

- シグナル: 複数の条件を組み合わせた if・switch・パターンマッチ、ルックアップテーブル
- 抽出: 条件（行）× ルール（列）と分岐先。条件の全組み合わせのうち、どの分岐でも処理されないもの・到達不能なもの・複数の分岐に該当し順序で決まるものを「未処理」「到達不能」「競合」として示す
- インタラクション: 2（条件の選択で該当ルールをハイライト）、7（分岐先での絞り込み）
- レイアウト: 表。条件は上、結果は下。未処理/到達不能/競合のルールは色と記号の両方で区別する

### トレース表

- シグナル: 状態を順に更新する処理、ループ、複数ステップの処理の流れ
- 抽出: 行=ステップ（`file:line` 付き）、列=状態・変数の値。値が変化したセルを強調する。入力値はコード上の分岐から代表値・境界値を選び「推定」と明示する
- インタラクション: 3（ステップ送り・スクラバー）、4（入力ケースの切り替え）、8（2つの入力ケースの比較）
- レイアウト: 表。現在のステップの行を強調し、それ以前の行を残す

### 変数と制約の二部グラフ

- シグナル: 入力検証・バリデーション、assert・事前条件、範囲チェック、型の制約、相互に依存する設定値
- 抽出: 左=変数（引数・入力値・設定値）、右=制約（検証の条件式）、辺=その制約に変数が現れること
- インタラクション: 2（変数値の入力で制約の充足/違反を色分け、違反理由と根拠のコード箇所を表示）、6（変数選択で関係する制約を強調）
- レイアウト: 2列。辺の交差を減らす順に並べる

### ガントチャート

- シグナル: タイムアウト、リトライ・バックオフ、sleep、スケジューラ・cron・周期実行、TTL
- 抽出: 行=処理、横軸=時間、バー=期間。依存を矢印で示す。タイミングチャートは処理の時間制約を表す
- インタラクション: 2（所要時間・間隔のスライダーでタイムアウト・リトライ枯渇を表示）、3（時間の再生）
- レイアウト: 横軸に目盛りと単位。期限は縦線で示す

## 共通のレイアウト規約

- 矢印は `<marker>` で定義する
- 色だけに頼らず、形・線種・記号でも区別する（凡例に載せる）
- 要素に `data-code="<コード要素ID>"` を付け、選択連動・ツールチップ・ドロワーの共通処理で使う
- 推定で補った要素・辺は破線や記号で区別する
- 要素数が多い図（目安: 30ノード超）は 1 の折りたたみまたは 9 のズームを使う

## レイアウトと可読性

要素が重なって見にくくならないこと、特にすべてのテキストが読めることを優先する。

- SVG の座標は自分で計算し、ノードの大きさはラベルの長さから決める。幅は全角1文字=1em、半角1文字=0.6em で見積もり、左右に余白を取る
- 長いラベル（`file:line` や関数シグネチャを含む）は `<tspan>` で折り返す（1行は全角15文字程度まで）。それでも収まらなければ ID と短い名前だけを表示し、全文はホバー・ドロワーで表示する
- ノード間は 24px 以上空ける。層状配置では層の間隔をその層の最大ラベル幅から決める。円周配置では半径をノード数とノード幅から決める
- 辺のラベルは背景付きで置き、ラベル同士・ラベルとノード・ラベルと他の辺が重ならない位置にずらす。同じノード間の複数の辺は曲線で離す。辺がノードを貫通しないよう迂回させる
- 表示時の文字サイズは 12px 以上を保つ。図が大きい場合は `viewBox` で縮小して文字を小さくせず、図の容器を横スクロールさせるか 9 のズームを使う
- 表やコード抜粋はセル内で折り返し、収まらない場合は容器を横スクロールさせる
- テキストはダーク/ライト両方で背景と十分なコントラストを取る。線と重なるテキストには `paint-order: stroke` で背景色の縁取りを付ける
- 強調・折りたたみ・切り替えなどで表示が変わった後も、上記を満たすようにする
- ツールチップ・ドロワーは図の要素を隠しきらない位置に出し、画面端で反転して見切れないようにする

### 重なりの検査

HTML 出力後に、図ごと（切り替え可能なビューはそれぞれ）にテキスト・ノード・辺のラベルの矩形が重なっていないことを確認し、重なりがあれば座標を修正する。

- ブラウザ自動操作（Playwright 等）が使える場合: `getBoundingClientRect()` で要素の矩形を総当たりで比較し、各テーマでスクリーンショットを撮って目視でも確認する
- 使えない場合: 座標計算の段階で各要素の矩形（見積もったテキスト幅を含む）を比較する
