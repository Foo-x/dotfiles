# Alloy 検証手順

対象コードの実装から抽出した振る舞いを Alloy でモデル化し、問題がないか検証する。対象コードのコメント・ドキュメント・テストは参照せず、実装のみからモデル化する。

alloyコマンドまたはalloy6コマンドが存在しないとき、nixが使える場合は nix shell コマンド、使えない場合は https://github.com/AlloyTools/org.alloytools.alloy/releases から環境に応じたバイナリをインストールする。

- 構造・制約・操作・状態遷移の抽出とモデル化
    - 各要素がどのコード要素（C）に対応するか `file:line` とともに明記する
    - データ構造の参照関係（リンク・所有・循環・共有）を signature とフィールドで表し、各操作は事前条件・事後条件・フレーム条件（変化しない部分）を明示した述語にする
    - カレントディレクトリにalsファイルを出力する
        - Alloy を知らないユーザーでもわかるようにすべての式・文を1行ずつコメントで説明する
- P の検証（充足可能性・不変条件・安全性・活性・デッドロック・到達性）
    - 反例のインスタンスは、対応するコード上の操作列（`file:line`）として報告する

## モード別設定

- quick
    - スコープは `for 4` 程度、時間ステップ数は `steps 5` 程度（`but` で調整）から始め、各コマンドに `timeout 120` を付ける
    - 反例がなければスコープを広げず、有界であることを明記する
- thorough
    - スコープを段階的に広げ（`for 6` → `for 8` → `for 10` 以上）、反例が出ない最大のスコープと、解けなくなったスコープを記録する
    - 活性は十分長いトレースで検証する
    - 各スコープの結果は有界である旨を明記する
