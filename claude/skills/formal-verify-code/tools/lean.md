# Lean 検証手順

対象コードの実装から抽出した振る舞いを Lean 4 でモデル化し、問題がないか検証する。対象コードのコメント・ドキュメント・テストは参照せず、実装のみからモデル化する。

leanコマンドが存在しないとき、nixが使える場合は nix shell コマンド、使えない場合は https://github.com/leanprover/elan の手順で elan をインストールする。

- 型・状態・関数・状態遷移の抽出とモデル化
    - 各要素がどのコード要素（C）に対応するか `file:line` とともに明記する
    - 対象関数は Lean の関数として制御フローを忠実に写す。ループは再帰で表現する
    - 整数は言語の型に合わせて、任意精度なら `Int`、固定幅なら `BitVec` / `UInt*` を選び、選択を明記する
    - カレントディレクトリにleanファイルを出力する
        - Lean を知らないユーザーでもわかるようにすべての式・文を1行ずつコメントで説明する
    - Mathlib 等の外部ライブラリに依存せず `lean <file>` 単体で検査できるようにする
- P の検証（充足可能性・不変条件・安全性・活性・デッドロック・到達性）
    - 性質は定理として証明する
    - 最終的な成果物に `sorry` を残さない
    - 証明できない性質は否定を証明するか、`decide` / `#eval` で具体的な反例（入力値）を示す

## モード別設定

- quick
    - `timeout 120 lean <file>` で検査する。モデルは主要な不変条件・安全性に絞る
    - 証明が時間内に終わらない性質は、小さな具体値での `decide` / `#eval` による確認に切り替え、任意の N での成立は「未検証」とする
- thorough
    - すべての性質について任意の N / 無限の定義域での証明を試みる
    - 帰納法の補題を立てるなど、証明を時間をかけて組み立てる
