# 図表の選定基準

図解の対象は「モデルの構造」と「反例・問題」の2つ。下表の「選ぶ条件」に当てはまる図表を1つまたは複数選ぶ。

## 対応表

| 図表 | 選ぶ条件 | 主なツール | モデルの構造で描く内容 | 反例・問題で描く内容 |
|---|---|---|---|---|
| 状態遷移図 | 状態を持つオブジェクト・状態変数がある | Quint | 状態、遷移（操作[ガード]/副作用）、初期状態 | 反例の経路を遷移上に強調する |
| トレース表 | 反例が複数ステップの実行列 | Quint, Alloy | — | 行=ステップ（`file:line` 付き）、列=状態変数。変化したセルと違反したステップを強調する |
| ペトリネット | 並行実行・ロック・同期・資源の取り合いがある | Quint | プレース、トランジション、初期マーキング | デッドロック・資源枯渇時のマーキング |
| シーケンス図 | スレッド・プロセス・外部サービス間でやりとりする | Quint | 正常系の呼び出し・メッセージ順序 | 競合・デッドロックに至るインターリーブ。接続関係が重要ならコミュニケーション図のビューに切り替えられるようにする |
| オブジェクト図 | 参照・所有・コレクションのデータ構造がある | Alloy | 型・フィールド・多重度（クラス図相当） | 反例のヒープ・インスタンス（循環参照、共有、ダングリング参照など） |
| 変数と制約の二部グラフ | 数値演算・分岐条件が中心 | Z3 | 変数（入力・中間値）と制約（分岐条件・事前/事後条件） | 反例の入力値と違反した制約。充足不能なら unsat core の制約を強調する |
| 決定表 | 複数条件の組み合わせで分岐する | Z3 | 条件 × ルール と結果（分岐先） | 処理されない・到達不能・競合する組み合わせ |
| 証明木 | 再帰・ループ不変条件・任意長データの正しさを証明する | Lean | 定理 → 補題 → 証明手法の分解 | 証明できなかったゴールと、その成立を妨げるコード箇所 |
| コールグラフ | 関数間の呼び出しが性質に関係する（再帰、コールバック、エラーの伝播） | 全般 | 対象の C とその呼び出し関係 | 反例の経路上の呼び出しを強調する |
| 依存関係グラフ | モジュール・コード要素間に初期化順序や前提がある | 全般 | C 間の依存と、P が依存する C | 問題に関与する C と、修正の影響範囲 |
| フローチャート | 関数内の分岐・ループが性質に関係する | 全般 | 対象関数の制御フロー | 反例が通る経路を `file:line` 付きで強調する |
| データフロー図 | 値の入力から出力・保存までの変換が性質に関係する | 全般 | プロセス、データストア、データフロー | 不正な値（範囲外、null、オーバーフロー）が生じてから違反に至る経路 |
| タイミングチャート | タイムアウト・リトライ・周期実行がある | Quint | 処理ごとの時間制約 | 期限超過・リトライ枯渇までの時間経過 |

## 選び方

- モデルの構造は、ツールごとに「主なツール」が一致する図表を少なくとも1つ選ぶ
- 反例は形に合わせて選ぶ
    - 実行列（Quint のトレース、Alloy の時系列インスタンス）: トレース表に加え、状態遷移図・シーケンス図・ペトリネットのうち構造に合うもの
    - インスタンス（Alloy）: オブジェクト図
    - 値の割り当て・充足不能（Z3）: 変数と制約の二部グラフ、分岐の組み合わせが問題なら決定表
    - 証明の失敗（Lean）: 証明木
    - 関数をまたぐ経路: コールグラフ、関数内の経路: フローチャート
- 同じ情報を複数の図で重複して描かない。トレース表と状態遷移図のように見方が異なる場合は併用してよい

## 共通の規約

- 図の要素に C・P の ID を付け、ホバーで内容と `file:line` を表示する
- 反例の図では、違反した状態・ステップ・制約を強調する
- 色だけに頼らず、形・線種・記号でも区別し、凡例に載せる

## レイアウトと可読性

要素が重なって見にくくならないこと、特にすべてのテキストが読めることを優先する。

- SVG の座標は自分で計算し、ノードの大きさはラベルの長さから決める。幅は全角1文字=1em、半角1文字=0.6em で見積もり、左右に余白を取る
- 長いラベル（`file:line` や関数シグネチャを含む）は `<tspan>` で折り返す（1行は全角15文字程度まで）。それでも収まらなければ ID と短い名前だけを表示し、全文はホバーで表示する
- ノード間は 24px 以上空ける。層状配置では層の間隔をその層の最大ラベル幅から決める
- 辺のラベルは背景付きで置き、ラベル同士・ラベルとノード・ラベルと他の辺が重ならない位置にずらす。同じノード間の複数の辺は曲線で離す。辺がノードを貫通しないよう迂回させる
- 表示時の文字サイズは 12px 以上を保つ。図が大きい場合は `viewBox` で縮小して文字を小さくせず、図の容器を横スクロールさせるかズーム・パンを付ける
- 表や差分はセル内で折り返し、収まらない場合は容器を横スクロールさせる
- テキストはダーク/ライト両方で背景と十分なコントラストを取る。線と重なるテキストには `paint-order: stroke` で背景色の縁取りを付ける
- ツールチップは画面端で反転し、見切れないようにする

### 重なりの検査

HTML 出力後に、図ごとにテキスト・ノード・辺のラベルの矩形が重なっていないことを確認し、重なりがあれば座標を修正する。

- ブラウザ自動操作（Playwright 等）が使える場合: `getBoundingClientRect()` で要素の矩形を総当たりで比較し、各テーマでスクリーンショットを撮って目視でも確認する
- 使えない場合: 座標計算の段階で各要素の矩形（見積もったテキスト幅を含む）を比較する
