# 図表の選定基準

図解の対象は「モデルの構造」と「反例・問題」の2つ。下表の「選ぶ条件」に当てはまる図表を1つまたは複数選ぶ。

## 対応表

| 図表 | 選ぶ条件 | 主なツール | モデルの構造で描く内容 | 反例・問題で描く内容 |
|---|---|---|---|---|
| 状態遷移図 | 状態とイベントがある | Quint | 状態、遷移（イベント[ガード]/副作用）、初期状態 | 反例の経路を遷移上に強調する |
| トレース表 | 反例が複数ステップの実行列 | Quint, Alloy | — | 行=ステップ、列=状態変数。変化したセルと違反したステップを強調する |
| ペトリネット | 並行・同期・排他・資源の取り合いがある | Quint | プレース、トランジション、初期マーキング | デッドロック・資源枯渇時のマーキング |
| シーケンス図 | 複数の主体間でメッセージをやりとりする | Quint | 正常系のメッセージ順序 | 反例のメッセージ順序。接続関係が重要ならコミュニケーション図のビューに切り替えられるようにする |
| オブジェクト図 | 関係・集合・参照の構造がある | Alloy | シグネチャ・フィールド・多重度（クラス図相当） | 反例のインスタンスと関係 |
| 変数と制約の二部グラフ | 数値・論理の制約が中心 | Z3 | 変数と制約、辺=制約に変数が現れること | 反例の値と違反した制約。充足不能なら unsat core の制約を強調する |
| 決定表 | 複数条件の組み合わせで結果が決まる | Z3 | 条件 × ルール と結果 | 未定義（結果が決まらない）・競合（結果が矛盾する）の組み合わせ |
| 証明木 | 帰納法・補題を組み合わせて証明する | Lean | 定理 → 補題 → 証明手法の分解 | 証明できなかったゴールと、その成立を妨げる仕様 |
| 依存関係グラフ | 仕様要素間に前提・依存がある | 全般 | 仕様IDと性質の依存 | 問題に関与する仕様と、修正の影響範囲 |
| フローチャート | 手順・分岐がある | 全般 | 処理と判断 | 反例が通る経路を強調する |
| データフロー図 | データの入出力・変換・保存がある | 全般 | プロセス、データストア、データフロー | 不正な値が生じてから違反に至る経路 |
| タイミングチャート | タイムアウト・期限・周期がある | Quint | 処理ごとの時間制約 | 期限超過・リトライ枯渇までの時間経過 |

## 選び方

- モデルの構造は、ツールごとに「主なツール」が一致する図表を少なくとも1つ選ぶ
- 反例は形に合わせて選ぶ
    - 実行列（Quint のトレース、Alloy の時系列インスタンス）: トレース表に加え、状態遷移図・シーケンス図・ペトリネットのうち構造に合うもの
    - インスタンス（Alloy）: オブジェクト図
    - 値の割り当て・充足不能（Z3）: 変数と制約の二部グラフ、条件の組み合わせが問題なら決定表
    - 証明の失敗（Lean）: 証明木
- 同じ情報を複数の図で重複して描かない。トレース表と状態遷移図のように見方が異なる場合は併用してよい

## 共通の規約

- 図の要素に仕様IDを付け、ホバーで内容を表示する
- 反例の図では、違反した状態・ステップ・制約を強調する
- 色だけに頼らず、形・線種・記号でも区別し、凡例に載せる

## レイアウトと可読性

要素が重なって見にくくならないこと、特にすべてのテキストが読めることを優先する。

- SVG の座標は自分で計算し、ノードの大きさはラベルの長さから決める。幅は全角1文字=1em、半角1文字=0.6em で見積もり、左右に余白を取る
- 長いラベルは `<tspan>` で折り返す（1行は全角15文字程度まで）。それでも収まらなければ ID と短い名前だけを表示し、全文はホバーで表示する
- ノード間は 24px 以上空ける。層状配置では層の間隔をその層の最大ラベル幅から決める
- 辺のラベルは背景付きで置き、ラベル同士・ラベルとノード・ラベルと他の辺が重ならない位置にずらす。同じノード間の複数の辺は曲線で離す。辺がノードを貫通しないよう迂回させる
- 表示時の文字サイズは 12px 以上を保つ。図が大きい場合は `viewBox` で縮小して文字を小さくせず、図の容器を横スクロールさせるかズーム・パンを付ける
- 表はセル内で折り返し、収まらない場合は表の容器を横スクロールさせる
- テキストはダーク/ライト両方で背景と十分なコントラストを取る。線と重なるテキストには `paint-order: stroke` で背景色の縁取りを付ける
- ツールチップは画面端で反転し、見切れないようにする

### 重なりの検査

HTML 出力後に、図ごとにテキスト・ノード・辺のラベルの矩形が重なっていないことを確認し、重なりがあれば座標を修正する。

- ブラウザ自動操作（Playwright 等）が使える場合: `getBoundingClientRect()` で要素の矩形を総当たりで比較し、各テーマでスクリーンショットを撮って目視でも確認する
- 使えない場合: 座標計算の段階で各要素の矩形（見積もったテキスト幅を含む）を比較する
