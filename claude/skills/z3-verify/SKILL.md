name: z3-verify
description: >
  仕様を Z3 でモデル化し、問題がないかを機械的に検証する。
disable-model-invocation: true
allowed-tools: Bash(type *)
---

与えた仕様を Z3Py（z3-solver）でモデル化し、問題がないか検証してください。

python3コマンドの有無: !`type python3 || true`
uvコマンドの有無: !`type uv || true`
nixコマンドの有無: !`type nix || true`

z3-solver は以下の優先順で用意してください。

1. uvが使える場合は `uv run --with z3-solver python <file>` で実行する
2. nixが使える場合は nix shell コマンドで python3 と z3-solver を用意する
3. どちらも使えない場合は python3 の venv を作成し `pip install z3-solver` する

- 型・状態・定数・操作・状態遷移の抽出とモデル化
    - モデル化するにあたって曖昧な記述があるときは指摘し、ユーザーに確認する
    - 各要素がどの仕様と対応するか明記する
    - カレントディレクトリにpyファイルを出力する
        - Z3 を知らないユーザーでもわかるようにすべての式・文を1行ずつコメントで説明する
        - 状態遷移は現在状態と次状態の変数組で遷移関係として表現する
        - 各検証項目の結果（sat / unsat / unknown）とモデル（反例）を出力する
- 充足可能性・不変条件・安全性・活性・デッドロック・到達性の検証
    - 不変条件は帰納的検証（初期状態で成立し、成立する状態から各操作後も成立する）で行い、失敗時は反例が到達可能かを有界モデル検査（BMC）で確認する
    - 到達性・安全性の BMC は検証したステップ数を明記し、網羅的でないことを明記する
    - unknown やタイムアウトが出た場合はその旨と原因（非線形算術、量化子等）を明記する

結果は以下の構成のHTMLファイル `z3-verify-report.html` で出力してください。

- 要約
    - 主要な問題と推奨する修正案
- 検証結果
    - 性質ごとに記載する（充足可能性・不変条件・安全性・活性・デッドロック・到達性）
    - 関係する仕様を併記する
- モデルの構造
    - 図解する
    - 表現できなかった、近似した点も併記する
- 仕様の曖昧点
    - 置いた仮定も併記する
- 反例・問題
    - 対象の仕様IDを併記する
    - 解釈を併記する（どのような欠陥か）
    - 仕様修正案を併記する（修正自体は行わない）
    - それぞれ図解する
- 検証範囲

仕様や反例などをIDで示す場合、その内容もわかるようにする。（併記するか、マウスホバーで見れるようにする）
図解は以下の候補から適したものを1つまたは複数選択して行う。

- 状態遷移図
- ペトリネット
- オブジェクト図
- シーケンス図
- 依存関係グラフ
- フローチャート
- データフロー図
- トレース表
- 証明木
- 変数と制約の二部グラフ
- ガントチャート
