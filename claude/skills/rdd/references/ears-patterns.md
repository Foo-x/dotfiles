# EARS 記法パターンガイド

要件は `<システム> SHALL <振る舞い>` を基本形とし、トリガーや条件のキーワードを前置する。キーワードと `SHALL` は英語のまま、他は日本語で書く。

| パターン | 構文 | 使う場面 |
| --- | --- | --- |
| 常時 (Ubiquitous) | `<システム> SHALL <振る舞い>` | 条件なしに常に成り立つ |
| イベント (Event-driven) | `WHEN <トリガー>, <システム> SHALL <振る舞い>` | 瞬間的な出来事への応答 |
| 状態 (State-driven) | `WHILE <状態>, <システム> SHALL <振る舞い>` | 状態が続く間の振る舞い |
| 異常 (Unwanted) | `IF <異常条件>, THEN <システム> SHALL <振る舞い>` | エラー・異常系 |
| 任意 (Optional) | `WHERE <機能・構成>, <システム> SHALL <振る舞い>` | 権限・設定・フラグで有効になる機能 |
| 複合 (Complex) | `WHILE <状態>, WHEN <トリガー>, <システム> SHALL <振る舞い>` | 状態とイベントの組み合わせ |

## 選択フロー

```
条件やトリガーがない                → 常時
瞬間的なイベントが起点               → WHEN
状態が継続している間                 → WHILE
異常・エラーが起点                   → IF ... THEN
機能の有無が構成・権限で決まる        → WHERE
状態とイベントの両方が必要           → 複合（条件は 2 つまで）
```

## 判別

- WHEN と WHILE: 「〜した時」と言えれば WHEN、「〜している間」と言えれば WHILE
- WHERE と IF: 正常な選択肢の一つなら WHERE、異常系なら IF。正常系のイベントに IF は使わない

## 例

| パターン | 良い例 |
| --- | --- |
| 常時 | 注文システム SHALL 金額を税込み整数円で保持する |
| イベント | WHEN 利用者が送信ボタンを押した時, 注文システム SHALL 注文状態を `pending` にする |
| 状態 | WHILE 決済処理中, 注文システム SHALL 送信ボタンを無効にする |
| 異常 | IF 在庫が 0 個の場合, THEN 注文システム SHALL 注文を拒否する |
| 任意 | WHERE 管理者権限がある場合, 注文システム SHALL 注文の強制取消操作を表示する |
| 複合 | WHILE 決済処理中, WHEN 利用者が戻る操作をした時, 注文システム SHALL 確認ダイアログを表示する |

## 悪い例

- 「適切に処理する」「高速に応答する」: 強度表現・形容詞で検証できない。数値と単位を使う（例: p95 で 300 ms 以下）
- 「保存し、メールを送信し、画面を更新する」: 複数の振る舞いを束ねている。要件を分ける
- 「配列を使って検索する」: 実装方式を書いている。外から観察できる振る舞いで書く
- 条件が 3 つ以上の複合: 分割する

## 書いた後の確認

- 1 要件 1 文で、1 つの振る舞いだけを述べているか
- 解釈が 1 つに決まるか。受け入れ基準で合否を判定できるか
- 数値に単位が付いているか
- 用語が用語集と一致しているか
