要件定義書を読み、図解したインタラクティブなHTMLを1つ出力してください。

引数: $ARGUMENTS

参照ファイル（必要になった時点で読む）:

- 図表の選定基準・抽出する情報・レイアウト指針: `${CLAUDE_SKILL_DIR}/references/diagrams.md`
- インタラクションの種類・実装規約: `${CLAUDE_SKILL_DIR}/references/interactions.md`

## 大原則

- 要件定義書は変更しない
- 書かれていない振る舞いを図に足さない。推測で補った箇所は「推定」と明示し、未決・TBD の箇所は図上で区別して表示する
- 図中の要素は必ず要件に紐づけ、ホバー／クリックで原文を確認できるようにする
- 外部依存のない単一HTML（インライン SVG + 素の JS/CSS）にする。CDN・外部フォント・外部画像は使わない

## 1. 読解

引数の要件定義書（参照されている関連文書を含む）を読み、以下を抽出する。

- 要件、用語、状態、アクター、データ、条件、時間制約、依存関係、未決事項

要件の識別:

- 文書に ID があればそれを使う
- なければ `R1, R2, ...` を採番し、原文の位置（見出し・行番号）と原文を対応付ける
- 書式は問わない（Markdown・テキスト・表・箇条書き。PDF・docx 等は読める範囲で）

## 2. 図表選定

`references/diagrams.md` の対応表で、要件の特徴に合う図表を選ぶ。

- コンテキスト図は概観として原則含める
- 引数に図表名があればそれに従う
- 1つの要件が複数の図に現れてよい。図に無理に当てはめず、適する要件がなければその図は作らない

選定した図表・選定理由・対象の要件 ID・採番した ID の対応を AskUserQuestion で1回確認する。ユーザーは図表を追加・除外できる。

## 3. インタラクション設計

各図について `references/interactions.md` から手法を選ぶ。インタラクションが理解を助けない図は静的のままにする。

## 4. HTML 生成

カレントディレクトリに `<要件定義書のファイル名(拡張子なし)>-visualize.html` を出力する。

構成:

- ヘッダー: 文書名・版・凡例（色・線種・記号の意味）
- 概観: コンテキスト図と、要件と図表の対応マップ（どの図で何がわかるか）
- 図ごとのセクション: タブまたは目次で移動する。各図に「対象要件」「読み方」を付ける
- 未反映: 図に載らなかった要件と未決事項の一覧
- 共通
    - ダーク/ライト両対応の CSS 変数、レスポンシブ
    - ID は内容がわかるようにする（併記、またはホバーで原文表示）。クリックでドロワーに原文を表示する
    - 要件データは `<script type="application/json">` に1か所で持ち、描画と分離する

## 5. 自己検証

- 全要件が図または「未反映」の一覧に現れること
- `references/diagrams.md` の「重なりの検査」に従い、要素が重ならずテキストが読めること
- 抽出した `<script>` に `node --check` が使えれば構文チェックする
- 条件切替・遷移再生などの結果が要件の原文と一致すること。評価ロジックには根拠の要件 ID を併記する
- ブラウザ自動操作（Playwright 等）が使えれば、コンソールエラーがないこと、各インタラクションが動くことを確認する

出力後は、ファイルパス・選んだ図表・図に載せられなかった要件（あれば）・推定で補った箇所（あれば）を簡潔に報告する。
