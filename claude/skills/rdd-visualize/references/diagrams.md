# 図表の選定基準

## 対応表

| 図表 | 主な対象要件 | 補足 |
|---|---|---|
| コンテキスト図 | システム境界・アクター・外部システム・ユースケース | 概観の起点。原則含める |
| 状態遷移図 | 状態とイベント・ガード | 階層状態・並行状態も含める |
| ペトリネット | 並行・同期・排他・資源の取り合い | |
| オブジェクト図 | データ・用語の構造と関係 | クラス図/ER図（構造）を含め、具体例（インスタンス）とトグルで切り替える |
| シーケンス図 | アクター間のやりとりの順序 | |
| コミュニケーション図 | アクター間の接続関係 | シーケンス図と同じデータを別ビューで切り替える |
| 依存関係グラフ | 要件・機能間の前提・依存 | |
| コールグラフ | 機能/API の呼び出し関係 | 要件に呼び出し関係が明記されている場合のみ |
| フローチャート | 手順・分岐 | 担当者が複数ならスイムレーンを使う |
| データフロー図 | データの入出力・保存・変換 | |
| 決定表 | 複数条件の組み合わせ→結果 | 条件の組み合わせ漏れ・矛盾を見つける |
| トレース表 | シナリオの実行ステップ × 状態・変数の値 | 実行トレースの意味に限る |
| トレーサビリティマトリクス | 要件 × 受け入れ基準/他要件/図要素 | トレース表と区別する |
| 証明木 | 目的→要件の導出・論理的帰結 | ゴール分解木を含める |
| 変数と制約の二部グラフ | 入力値・パラメータの制約 | |
| ガントチャート | 期間・期限・稼働時間帯 | タイムアウト・リトライ間隔などのタイミングチャートを含める |

## 図表ごとの指針

各図表は「シグナル → 抽出 → インタラクション → レイアウト」の順に記す。インタラクション名は `interactions.md` の番号に対応する。

### コンテキスト図

- シグナル: 「〜と連携する」「〜から受け取る」「〜が利用する」、利用者・外部システムの列挙、スコープの対象/対象外
- 抽出: 中心にシステム、周囲にアクター・外部システム、辺にやりとりするデータ・操作。対象外は破線で区別する
- インタラクション: 1（アクターのクリックで関連要件をドロワー表示）、6（アクター選択で関連要件・他の図を強調）
- レイアウト: 中央にシステム、アクターを円周上に配置。人と外部システムで形を変える

### 状態遷移図

- シグナル: 「〜の間」「〜状態」「〜したら〜になる」「〜の場合のみ」
- 抽出: ノード=状態、辺=イベント[ガード]/副作用。初期・終了状態、禁止された遷移（「〜できない」）も記す
- インタラクション: 3（イベントボタンで発火し前後状態と副作用を表示）、2（ガード条件のトグル）、1（階層状態の折りたたみ）
- レイアウト: 正常系の流れを左→右の主軸にし、異常系・戻りを下側に迂回させる。自己ループは上に付ける

### ペトリネット

- シグナル: 「同時に」「〜が揃ったら」「排他」「上限N件」「資源」
- 抽出: プレース=状態/資源、トランジション=イベント/処理、トークン=件数/資源数。初期マーキングは要件の上限・容量から決める
- インタラクション: 3（トークンゲーム。発火可能な遷移のみ有効化、デッドロックの可視化）
- レイアウト: 左→右の層状配置。プレースは円、トランジションは棒/四角

### オブジェクト図

- シグナル: 用語集、「〜は〜を持つ」「〜は複数の〜からなる」、データ項目の列挙
- 抽出: 構造（型と関係・多重度）と、要件中の具体例（インスタンスと属性値）
- インタラクション: 4（構造⇔インスタンスの切り替え）、1（属性の折りたたみ）、6（関係先の強調）
- レイアウト: 関連の多い型を中央に配置。多重度を辺の両端に付ける

### シーケンス図

- シグナル: 「〜が〜に要求する」「〜を返す」「〜の後」「〜するまで待つ」、エラー応答
- 抽出: ライフライン=アクター/システム/外部、メッセージ=順序付きの操作とデータ。正常系と異常系（代替・例外）を分ける
- インタラクション: 3（ステップ送り・自動再生）、4（正常/異常のタブ、コミュニケーション図との切り替え）
- レイアウト: 上→下が時間。ライフラインは左→右に、やりとりの多い順に隣接させる

### コミュニケーション図

- シグナル: シーケンス図と同じ。順序より「誰と誰が接続するか」が重要な場合
- 抽出: オブジェクト間のリンクと、辺上の番号付きメッセージ（シーケンス図のデータを再利用する）
- インタラクション: 4（シーケンス図との切り替え）、6（メッセージ番号の選択で前後を強調）
- レイアウト: オブジェクトを円周上に配置し、辺に番号とメッセージ名を付ける

### 依存関係グラフ

- シグナル: 「〜が前提」「〜に依存」「〜の後に実施」「〜を含む」
- 抽出: ノード=要件/機能、有向辺=依存。循環は強調する
- インタラクション: 6（上流/下流/影響範囲の強調）、7（種別・優先度で絞り込み）、9（大規模時）
- レイアウト: 依存先を左、依存元を右の層状配置。辺の交差を減らす

### コールグラフ

- シグナル: 「〜を呼び出す」「〜APIを使う」が明記されている場合のみ
- 抽出: ノード=機能/API、辺=呼び出し。同期/非同期を線種で区別する
- インタラクション: 6（呼び出し経路の強調）、1（モジュール単位の折りたたみ）
- レイアウト: 呼び出し元を左、呼び出し先を右の層状配置

### フローチャート

- シグナル: 「〜の場合は〜」「〜でなければ」「繰り返し」「〜の手順」
- 抽出: 開始/終了、処理、判断（菱形）、分岐ラベル。担当者が複数ならスイムレーン
- インタラクション: 2（判断の入力で通る経路を強調）、3（ステップ再生）
- レイアウト: 上→下。判断は「はい」を下、「いいえ」を横に出す

### データフロー図

- シグナル: 「〜を保存する」「〜を出力する」「〜を変換する」、データ項目名
- 抽出: プロセス、データストア、外部実体、データフロー（名前付き）
- インタラクション: 6（データ項目の追跡: 入力から出力までの経路を強調）、1（プロセスの分解）
- レイアウト: 外部実体を両端、プロセスを中央、データストアを下側に置く

### 決定表

- シグナル: 「AかつBの場合〜」「〜のとき〜、それ以外は〜」が複数並ぶ条件列挙
- 抽出: 条件（行）× ルール（列）と結果。条件の全組み合わせのうち、要件に記載のないもの（漏れ）と矛盾するものを「未定義」「競合」として示す
- インタラクション: 2（条件の選択で該当ルールをハイライト）、7（結果での絞り込み）
- レイアウト: 表。条件は上、結果は下。未定義/競合のルールは色と記号の両方で区別する

### トレース表

- シグナル: 受け入れ基準のシナリオ、Given/When/Then、具体的な入力例と期待結果
- 抽出: 行=ステップ（イベント）、列=状態・変数の値。値が変化したセルを強調する
- インタラクション: 3（ステップ送り・スクラバー）、4（シナリオの切り替え）、8（2つのシナリオの比較）
- レイアウト: 表。現在のステップの行を強調し、それ以前の行を残す

### トレーサビリティマトリクス

- シグナル: 要件と受け入れ基準、検証方法、関連文書の対応
- 抽出: 行=要件、列=受け入れ基準/検証/図。対応がない行・列（漏れ）を強調する
- インタラクション: 7（絞り込み）、6（行/列の選択で関連を強調）
- レイアウト: 表。対応セルは記号と色で示す

### 証明木

- シグナル: 目的・成功指標、「〜のために〜」「〜を満たすには〜が必要」
- 抽出: ルート=目的/上位ゴール、子=達成に必要な下位要件（AND/OR を区別する）。根拠がない要件・目的に結びつかない要件を示す
- インタラクション: 1（ノードの折りたたみ）、5（パンくず）、7（未反映の強調）
- レイアウト: 上→下のツリー。AND は弧で結ぶ

### 変数と制約の二部グラフ

- シグナル: 「〜は1〜100」「AとBの合計は〜以下」「〜は必須」「〜のとき〜は不可」
- 抽出: 左=変数（入力値・パラメータ）、右=制約、辺=その制約に変数が現れること
- インタラクション: 2（変数値の入力で制約の充足/違反を色分け、違反理由と根拠の要件を表示）、6（変数選択で関係する制約を強調）
- レイアウト: 2列。辺の交差を減らす順に並べる

### ガントチャート

- シグナル: 期限、稼働時間帯、「〜以内」「〜ごとに」、タイムアウト、リトライ間隔
- 抽出: 行=タスク/処理、横軸=時間、バー=期間。依存を矢印で示す。タイミングチャートは処理の時間制約を表す
- インタラクション: 2（期間・所要時間のスライダーで制約違反を表示）、3（時間の再生）
- レイアウト: 横軸に目盛りと単位。期限は縦線で示す

## 共通のレイアウト規約

- 矢印は `<marker>` で定義する
- 色だけに頼らず、形・線種・記号でも区別する（凡例に載せる）
- 要素に `data-req="<要件ID>"` を付け、選択連動・ツールチップ・ドロワーの共通処理で使う
- 要素数が多い図（目安: 30ノード超）は 1 の折りたたみまたは 9 のズームを使う

## レイアウトと可読性

要素が重なって見にくくならないこと、特にすべてのテキストが読めることを優先する。

- SVG の座標は自分で計算し、ノードの大きさはラベルの長さから決める。幅は全角1文字=1em、半角1文字=0.6em で見積もり、左右に余白を取る
- 長いラベルは `<tspan>` で折り返す（1行は全角15文字程度まで）。それでも収まらなければ ID と短い名前だけを表示し、全文はホバー・ドロワーで表示する
- ノード間は 24px 以上空ける。層状配置では層の間隔をその層の最大ラベル幅から決める。円周配置では半径をノード数とノード幅から決める
- 辺のラベルは背景付きで置き、ラベル同士・ラベルとノード・ラベルと他の辺が重ならない位置にずらす。同じノード間の複数の辺は曲線で離す。辺がノードを貫通しないよう迂回させる
- 表示時の文字サイズは 12px 以上を保つ。図が大きい場合は `viewBox` で縮小して文字を小さくせず、図の容器を横スクロールさせるか 9 のズームを使う
- 表はセル内で折り返し、収まらない場合は表の容器を横スクロールさせる
- テキストはダーク/ライト両方で背景と十分なコントラストを取る。線と重なるテキストには `paint-order: stroke` で背景色の縁取りを付ける
- 強調・折りたたみ・切り替えなどで表示が変わった後も、上記を満たすようにする
- ツールチップ・ドロワーは図の要素を隠しきらない位置に出し、画面端で反転して見切れないようにする

### 重なりの検査

HTML 出力後に、図ごと（切り替え可能なビューはそれぞれ）にテキスト・ノード・辺のラベルの矩形が重なっていないことを確認し、重なりがあれば座標を修正する。

- ブラウザ自動操作（Playwright 等）が使える場合: `getBoundingClientRect()` で要素の矩形を総当たりで比較し、各テーマでスクリーンショットを撮って目視でも確認する
- 使えない場合: 座標計算の段階で各要素の矩形（見積もったテキスト幅を含む）を比較する
