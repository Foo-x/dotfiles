# CLAUDE.md

## Git

ユーザーが指示しない限りステージ、コミット、pushはしない。

コミットメッセージは Conventional Commits に従う。

- 1行目は変更内容に応じたtypeを付けて50文字以内で記載
    - 適宜 `type(scope):` の形式でscopeも含める
- 必要な場合のみ空行を挟んで詳細を1行72文字以内で記載
- 必要な場合のみ空行を挟んでフッターを1行72文字以内で記載
- チケットIDを含める場合はフッターに記載し、それ以外には記載しない
- すべて英語

プルリクエストは指示がない限りDraftで作成する。

プルリクエストの説明はテンプレートの構成に従い、日本語で記載する。

## jj

gitコマンドを使用する前にjjリポジトリかどうか確認し、jjリポジトリの場合はjjコマンドを使用する。

jjコマンドで実現できない操作はgitコマンドを使用する。

squash workflow で開発する。

1. 作業開始時に working copy が空のchangeでない場合は `new` で空のchangeを作成する
2. 作業内容に `describe` でコミットメッセージを付けた場合は追加で `new` も行う
3. 作業内容を既存のコミットに含める場合は `squash` で行う

コミットメッセージやプルリクエストの扱い方はGitと同様。

## コードコメント

コードコメントには非自明なWHYだけを書く。隠れた制約や直観的でない実装にした理由など、コードから復元できない情報に限る。

コードを読めばわかるWHAT、変更履歴、チケットIDなどは書かない。
チケットIDを残したい場合はコミットメッセージのフッターやプルリクエストの説明に記載する。
